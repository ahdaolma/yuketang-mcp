# 课程笔记本、扫码登录与课件整理

用户要求：暂不发布新版；先改好笔记分类，排查切到微信扫码的后台登录，并支持课件时间、老师等排序和时间标记。此前阅读、标题、MIT 与风险声明的改动继续保留。

## 笔记组织

借鉴 OneNote 的笔记本/分区/页面层级、Notion 的筛选视图和 Obsidian 的标签检索，用两层分类承载本软件的课程笔记本与章节/专题。标签仍用于跨课程主题，置顶、待复习、课堂笔记提供快捷视图，不复制笔记。与继续沿用单层分类相比能按课程查找；与纯标签相比保留明确的课程归属。

原分类原 ID 保留为根笔记本，原笔记归属不变。章节最多一层，同一父级下名称唯一。选中根笔记本时包含其章节的笔记；选择章节只显示该章节。未整理笔记单独可见。提供可搜索、限高且固定关闭的笔记本选择器，显示层级、数量和当前位置；管理、重命名、新建章节和移动均沿用宽幅圆角面板。笔记支持多选后批量移动，不能逐份重复操作。

新课堂笔记可依据已授权课堂的 region、账号散列与 classroomId 关联课程笔记本，不以可变课程标题作为唯一身份。重新进入同一班级复用笔记本；不同账号不合并。用户已手动整理的旧笔记保持归属。没有可靠身份的历史记录不猜测。删除章节将其笔记移到所属笔记本；删除笔记本及章节前确认数量，笔记回到未整理，正文、草稿和标记均保留。

本地加密数据新增父级与课堂关联字段。笔记备份保存父子结构，导入重映射父子 ID；不导出账号课堂关联键。旧备份没有父级字段时仍按根笔记本读取。

## 扫码登录

先复查现有真实 TLS/WebSocket + HOME/返回设备用例，覆盖二维码在微信确认前不被替换。检查 Activity 重建、切后台、通知返回、取消、过期、迟到回调与前台服务结束路径。只修复有证据的问题；不把合成确认当成真实微信账号验证。

目前 MainActivity 使用 Application 持有的 ViewModel，普通 Activity 重建不应清除连接；前台服务只在扫码期间运行。扫码提示和状态必须清楚，后台返回后仍显示当前二维码/已保存账号，不强迫重新扫码。服务被系统结束时不得继续无期限显示正在等待。

## 课件目录

课程明确保存老师和学期字段。课程列表可按课程浏览或老师分组。课件目录提供时间倒序、时间正序、名称、老师顺序，课程页与学习资料入口使用同一规则。分页接口只对已加载批次排序，界面明确说明范围，不将单批排序冒充全部历史排序。

区分真实课件创建时间、活动发布时间、上课时间和本机导入/修改时间。优先显示接口实际提供的创建时间；只有发布时间或上课时间时使用对应标签。缺失创建时间明确写未提供，不能用导入时间、当前时间或编号代替。秒/毫秒时间戳、带时区 ISO 日期与常见日期格式按真实时刻排序，缺失或无法识别的时间排在末尾且稳定。同一老师内继续按时间排序。

## 视觉与验证

延续现有 Material 颜色、宽幅圆角与清楚的选中状态。去掉无限横向堆放分类的方式；普通页面可以纵向阅读，展开的选择/管理面板统一限高、内部滚动且关闭入口固定。上课卡片保留。
